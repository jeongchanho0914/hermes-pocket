# Android conversation context and compaction

Production `DirectAgent.run` no longer uses the old 60,000-character default or 240,000-character ceiling. `contextChars` is ignored by its request path. The old `trimHistory` helper remains only for historical regression tests; it is not called by the running agent.

The API `/models` catalog preserves context/output metadata when present. Store selects the entry matching the exact configured endpoint and model. Metadata takes priority over the small official catalog. Provider/model maxima are not guaranteed for unknown models: a 128,000-token working estimate is explicitly marked unverified. Known specifications apply only to the official endpoint, not unrelated deployments with the same model name.

Official sources checked 2026-10-04:

- [Xiaomi MiMo-V2.6-Flash](https://mimo.mi.com/models/en-US/mimo-v2.6-flash): 1M context, 128K maximum output, represented conservatively as decimal 1,000,000 and 128,000.
- [GPT-5.2](https://developers.openai.com/api/docs/models/gpt-5.2): 400,000 context, 128,000 maximum output.
- [GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1): 1,047,576 context, 32,768 maximum output. OpenAI Docs skill was used for these official model facts.

A maximum output allowance is not a requirement to generate that many tokens. Ordinary requests reserve/allow up to 8,192 response tokens (bounded by the model output maximum); compaction allows up to 4,096. System text, enabled tool schemas, replay-required reasoning, message overhead, and current pixel input estimates count against the input budget. Approximate multilingual token counting is conservative, and real streamed prompt usage adjusts the estimate upward. Provider usage is requested on known compatible providers. Exact vendor tokenizers are not bundled, and this estimate is not reported as exact counting.

At 88% of the available input budget, the configured model generates a structured checkpoint containing goals, durable user facts, completed/denied/verified actions, pending work, filenames/skills/identifiers, and errors. Recent messages remain intact with assistant tool requests and their responses aligned. Current user instructions remain verbatim. The full original transcript remains in SQLite, including complete reasoning fields needed by MiMo/DeepSeek replay. Summarization excludes reasoning fields and pixel payloads. A separately persisted checkpoint includes a hash of the covered original messages; changed or stale history invalidates it.

Only an explicitly classified HTTP 400/413/422 context error can cause one compact-and-resubmit attempt. Authentication, quota, malformed streams, missing completion markers, and interrupted responses never replay actions. The retry concerns the rejected model request only: previously executed tools are not repeated. Pixel inputs are discarded before a retry, so they cannot be replayed as fresh observations. A numeric maximum is extracted only from a narrow provider error phrase; provider text is never exposed in diagnostics. An unknown endpoint without numeric evidence uses a conservative fallback after context rejection, still marked unverified.

`DirectAgent.compact(session, config, token)` uses the same guarded runtime ownership as chat and powers the typed native `compactConversation` action. Empty, partial/length-stopped, or unstructured summaries are rejected before checkpoint persistence. Cancellation preserves the previous checkpoint and full original transcript. A single input that cannot fit is reported honestly; it is not silently clipped.

Implementation is an Android adaptation of pinned Hermes Agent `d795726f78e532ca31655f74656b4be63a907581`, particularly `agent/context_compressor.py` (head + iterative structured summary + protected pair-aligned tail), `agent/model_metadata.py`, and `hermes_state_compression.py` (preserved local history). It does not copy Python source. Hermes MIT license is retained with the existing upstream source and bundled skill provenance. Oversized historical regions use multiple bounded model summary requests rather than discarding unsampled records. Oversized completed tool batches are summarized as a whole; individual large records are split into ordered quoted JSON fragments, preserving every Unicode character for the summarizer while the original transcript remains intact. A hard limit of 32 summary calls aborts before checkpoint persistence; this is a deliberate Android difference from the original single-call auxiliary route. Summary API calls may add latency and usage.

Validation: `ContextCompactorHarness` exercises actual loopback HTTP rejection → one summary → one resubmit, unchanged stored original messages, safe context error classification, preserved facts/current instructions/tool pairing, checkpoint reload/hash invalidation, rejection of partial summary, oversized completed tool-batch and Unicode fragment coverage, and exact known/model API limits. Existing DirectAgent, ModelProgress, and ScreenVision fixture suites verify reasoning replay and ephemeral pixels remain intact. These are simulated APIs, not live provider or physical Android proof.
