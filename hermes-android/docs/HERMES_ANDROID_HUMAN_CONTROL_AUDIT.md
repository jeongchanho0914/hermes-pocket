# Ordinary owner phone control: current Android capability gaps

Audit date: 2026-10-04. Read-only source inspection; no phone, keys, build or tests used. This is a current native capability audit, not a claim that every Android 16 device permits every shell command. App manifest currently targets SDK 35. The user-authorized goal is broad ordinary human phone operation with Accessibility and Shizuku; actual Android/SELinux/service identity and user-established permissions still determine execution.

Shizuku UserServices run as actual root UID 0 or adb shell UID 2000; shell is not root. The checked-in bridge reports actual UID and rejects other identities. [Official Shizuku API](https://github.com/RikkaApps/Shizuku-API/blob/master/README.md?plain=1), [local service](../app/src/main/java/dev/chanho/hermes/PrivilegedPhoneService.java#L80).

## Exact policy gates to refactor

1. [PhoneAccessibilityService.protectedPackage:46](../app/src/main/java/dev/chanho/hermes/PhoneAccessibilityService.java#L46) blanket-protects Settings and SystemUI. [allowedRoot:80](../app/src/main/java/dev/chanho/hermes/PhoneAccessibilityService.java#L80) applies the rule to observation and all actions. Fresh-target `resolve` and post-snapshot gesture checks are valuable and should remain.
2. [Store.allowed:180](../app/src/main/java/dev/chanho/hermes/Store.java#L180) calls the same screen predicate through `OwnerApprovalPolicy.allowsApp`; [DeviceTools.requireAllowed:241](../app/src/main/java/dev/chanho/hermes/DeviceTools.java#L241) also rejects it. Removing one local check will therefore not enable Settings. Separate package eligibility for launching/force-stop from live-screen surface eligibility for observation and control.
3. [PhonePrivilegePolicy:8](../app/src/main/java/dev/chanho/hermes/PhonePrivilegePolicy.java#L8) has independent force-stop protection. [validateSetting:21](../app/src/main/java/dev/chanho/hermes/PhonePrivilegePolicy.java#L21) permits only five system keys; write validation makes `user_rotation` read-only. [service force-stop:103](../app/src/main/java/dev/chanho/hermes/PrivilegedPhoneService.java#L103) additionally rejects all system apps.
4. [TerminalTools schemas:29](../app/src/main/java/dev/chanho/hermes/TerminalTools.java#L29) permit `app` or `shizuku` only. [terminal gate:50](../app/src/main/java/dev/chanho/hermes/TerminalTools.java#L50) requires enabled terminal plugin, unlocked active request, all device scope and live authorized service for Shizuku. Ordinary owner approval mode already has an `auto` option, scoped to active unlocked requests; changing capability checks does not require adding repeated per-action confirmation.

## Primary platform references and limits

Android Accessibility exposes global actions such as Quick Settings/notifications/recents and gesture dispatch, with service capabilities and supported-action checks. [AccessibilityService reference](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService). `Settings.System.canWrite` requires established special write access for the ordinary app path. [Settings.System reference](https://developer.android.com/reference/android/provider/Settings.System).

Ordinary target-SDK-33+ applications cannot silently toggle Bluetooth with deprecated `enable`/`disable`; use an actual supported user GUI or privileged adapter. [Android target behavior](https://developer.android.com/about/versions/13/behavior-changes-13). Current AOSP exposes Bluetooth shell `enable`/`disable` commands, but this establishes an implementation candidate, not success on this user's OEM Android 16 device. [AOSP Bluetooth shell implementation](https://android.googlesource.com/platform/packages/modules/Bluetooth/+/refs/heads/master/service/src/com/android/server/bluetooth/BluetoothShellCommand.java).

Android 16 sensitive accessibility data protections can prevent observation/action even when a service is enabled. Preserve those platform outcomes; do not claim a capability that hides or bypasses them. [Android 16 security explanation](https://developer.android.com/blog/posts/enhancing-android-security-stop-malware-from-snooping-on-your-app-data). No device-level success was verified in this audit.
